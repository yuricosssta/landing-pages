# landing-pages

Next.js 16 project for creating landing pages integrated with Sistema Cazuá.

## Commands

| Command | Description |
|---------|-------------|
| `pnpm dev` | Start dev server |
| `pnpm build` | Production build |
| `pnpm start` | Start production server |
| `pnpm lint` | Run ESLint |

Package manager: **pnpm@10.33.0** (specified in package.json)

## Stack

- **Framework**: Next.js 16.3.4 (App Router)
- **React**: 19.2.8
- **Language**: TypeScript 5 (strict mode)
- **Styling**: TailwindCSS v4 (using `@import "tailwindcss"`)
- **Fonts**: Geist Sans & Geist Mono via `next/font/google`
- **Linting**: ESLint 9 with `eslint-config-next` (core-web-vitals + typescript)
- **State**: Redux Toolkit (auth, posts, user, organizations, resources, planning)
- **Forms**: react-hook-form + zodResolver with Stepper pattern
- **Validation**: Zod
- **UI**: Shadcn/Radix "new-york" style, RSC enabled

## Architecture Essentials

- **App Router** in `src/app/` with route groups `(main)`
- **BFF layer**: Route handlers in `src/app/api/*` proxy to NestJS backend
- **Redux Toolkit** global state: `src/lib/redux/store.ts` (auth, posts, user, organizations, resources, planning)
- **never call backend directly from client when BFF handler exists**
- **ObjectId validation**: Regex `/^[0-9a-fA-F]{24}$/` — **never import mongoose in frontend**

## Conventions

- **Commits**: Conventional Commits (`feat(editorial): ...`, `fix: ...`, `style: ...`)
- **Forms**: react-hook-form + zodResolver with Stepper pattern
- **Validation**: Zod schemas in `src/validations/*.zod.ts` and `src/lib/dto/*.schema.ts`
- **API calls**: Client → BFF (`/api/*`) → NestJS backend; server utils in `src/lib/api/serverUtils.ts`
- **Tailwind v4**: Via `@tailwindcss/postcss` (no `tailwind.config.ts`); globals in `app/globals.css`
- **Shadcn/Radix**: "new-york" style, RSC enabled, aliases `@/components`, `@/lib/utils`

## Environment

- `.env` at repo root: `COMPOSE_FILE=docker-compose.dev.yml`
- Frontend env (build args): `NEXT_PUBLIC_API_BASE_URL`, `NEXT_PUBLIC_INITIAL_MAP_CENTER`
- Production uses `output: 'standalone'` (Dockerfile multi-stage)

## TypeScript Config

- Target: ES2017
- Module: ESNext (bundler resolution)
- Path alias: `@/*` → `./*`
- Includes generated `.next/types/**/*.ts` and `.next/dev/types/**/*.ts`

## ESLint

Extends `eslint-config-next/core-web-vitals` and `eslint-config-next/typescript`. Default ignores: `.next/**`, `out/**`, `build/**`, `next-env.d.ts`.

## File Structure

```
src/
  app/              # App Router pages (route groups, API handlers)
    api/            # BFF route handlers proxying to NestJS
    (main)/         # Main route group
  lib/
    redux/          # Redux store & slices
    api/            # Server utilities (serverUtils.ts)
    dto/            # Zod schemas
  validations/      # Zod validation schemas
  components/       # Shadcn/Radix components
types/              # Auto-generated Next.js route types (do not edit manually)
public/             # Static assets
components.json     # Shadcn config (style: new-york, RSC: true)
```

## Key Files to Know

- `src/lib/api/serverUtils.ts` — BFF helpers (auth header, org headers, API URL resolution)
- `src/lib/redux/slices/*.ts` — state slices
- `components.json` — Shadcn config (style: new-york, RSC: true)

## Gotchas

- Redux store imported dynamically in axios interceptors (avoids circular deps)
- 401 response → dispatches `sessionExpired()` + clears org state
- `NEXT_PUBLIC_API_BASE_URL` used server-side (BFF fetch)
- No `tailwind.config.ts` — Tailwind v4 config is in CSS
- Backend service commented in docker-compose; frontend expects NestJS at `localhost:3001` or `INTERNAL_API_URL`
- Types in `types/` are generated by Next.js — do not edit manually
- Uses CSS variables for theming (light/dark mode via `prefers-color-scheme`)
